# МАРШРУТИЗАТОР ПАМЯТИ (Memory Router)

Единая точка правды о том, какая память для чего. Не путай системы — и агент перестанет «забывать».

## 1. Перед любой нетривиальной задачей — сначала ПАМЯТЬ, потом код
1. `memory_smart_search` (agentmemory, MCP) — запрос по теме задачи + имя проекта, limit 5–10. **Один вызов до первого чтения кода.**
2. Перед повторением задачи, где вас уже поправляли: `memory_lesson_recall` (та же тема).
3. Если тема — про код и архитектуру репо: `graphify query "<вопрос>"` (или codemap — см. `codemap_rule.md`).

## 2. В момент решения/находки — сохраняй сразу (не в конце сессии)
* Решение / договорённость / неочевидная причина:  
  `memory_save` → content = «что + ПОЧЕМУ», concepts = 2–5 конкретных тегов (`cursor-pagination`, не `code`), files = реальные пути.
* Пользователь поправил подход — это **урок**, не факт:  
  `memory_lesson_save` (правило + последствие, confidence 0.7).
* Не сохраняй то, что и так видно из кода/репо; никаких секретов в content.

## 3. Куда что сохранять (не путать!)

| Тип знания | Инструмент / место | Пример |
| :--- | :--- | :--- |
| Сессии, решения, «почему», гочи, уроки | **agentmemory** (`memory_save`, `memory_lesson_save`) | «выбрали курсорную пагинацию, потому что offset-скан тормозит после 100k строк» |
| Активы: репозитории, железо, сервисы, где что лежит | **INVENTORY.md** (только точечный поиск! см. ниже) + краткая запись в agentmemory | новый репозиторий, новый сервис на сервере |
| Статьи/веб-материалы | bridge `memory` (action=save/recall, topic) | «сохрани статью про RRF» |
| Книги (FTS5, Linux-сервер) | `book_search` | «найди в книгах про байесовские методы» |
| Сметы/светотехника (Smart Light AI) | `_AI_CACHE\memory\rules_and_preferences.json` + `00_Ответы_ИИ\TEAM_CHAT.md` | стандарты IEC/фотометрия, логистика CMR, матрица производителей |
| Компактный реестр проектов/железа | Слот `project_registry` (agentmemory, global) | быстрый контекст для любых задач |
| Код и архитектура текущего репо | `graphify` (query/path/explain) + `docs/codemap/` | «кто вызывает e2e gate» |

## 4. Возвращение к работе и обзоры
* «Где мы остановились / продолжим» → `handoff` (или `memory_sessions` → `memory_recall`).
* «Что делали за неделю / сводка» → `recap`.
* «Что было по теме X» → `recall` (`memory_smart_search`).
* Полный список сессий — `session-history`.

## 5. Память — не выдумка
* Пустой поиск — это ответ: скажи «не нашёл», предложи 2–3 альтернативных термина. **Никогда** не изобретай «воспоминания», session id или важность.
* Противоречия: слово пользователя > вывод агента; записи из чужих сессий помечай как таковые.

## 6. Если инструменты памяти недоступны
* Не изображай память. Скажи пользователю: «сервер памяти не отвечает / MCP не подключён» и загляни в `skills/_shared/TROUBLESHOOTING.md` (быстрый чек: демон на :3111 → запись в `~/.gemini/config/mcp_config.json` → перезапуск хоста).

## 7. Гигиена больших реестров
* `INVENTORY.md` (~93 КБ) и `LIBRARY_INDEX.md` (~115 КБ) **никогда не читать целиком**. Только точечный поиск:  
  `Select-String -Path 'D:\Создание программ\INVENTORY.md' -Pattern 'ключ'` или grep; для книг — `book_search`.
