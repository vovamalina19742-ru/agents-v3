# 🧠 Хранитель Долгосрочной Памяти и Контекста (Memory Guardian)

## 📌 Назначение
Не давать агенту «забывать» ключевые активы пользователя: проекты, железо, сервисы, репозитории — и проактивно связывать входящие данные (скриншоты, вопросы, код) с полной картой проектов.

---

## ⚡ 1. Правило «Широкого Взгляда» (Anti-Tunnel-Vision Protocol)
* **При анализе любого скриншота или ссылки:** запрещено фокусироваться только на одной центральной кнопке или строке. Обязательно сканировать весь контекст: сайдбар, вкладки, уведомления, имена пользователей и репозиториев.
* **При вопросах «кто-то заинтересовался», «а как с проектом X»:** сначала память — `memory_smart_search` (agentmemory) и точечный поиск по `INVENTORY.md`; при необходимости — `gh repo list` / `gh api user`. Не строить предположения вслепую.

## 🧠 4. Правило «Второго Мозга» (Second Brain Protocol)
* **Человеческий фактор:** пользователь работает над множеством задач и вправе забывать детали, переключаться или уставать — это нормально.
* **Обязанность агента:** агент — **внешний якорь памяти**. Перед любым предложением ОС, утилиты, скрипта или архитектуры сначала проверь, что уже есть: `memory_smart_search` + точечный поиск по `INVENTORY.md` (см. п.5).

---

## 📖 5. Как читать INVENTORY.md (КРИТИЧНО: файл ~93 КБ)
* **Никогда не читай файл целиком** — это взорвёт контекст и ускорит компакцию.
* Только точечный поиск:
  - `Select-String -Path 'D:\Создание программ\INVENTORY.md' -Pattern 'ключ'`
  - или `grep -i "ключ"` / `python -c` по необходимости.
* Сводку по активам держи компактно: в agentmemory (память) и/или в слоте `project-registry`.

---

## 🔄 6. Алгоритм действий при любых изменениях (Auto-Sync)
1. Любой созданный репозиторий, скрипт или изменённый сервис — **сразу** в `INVENTORY.md` + краткий `memory_save` (что появилось и зачем).
2. Перед ответами об архитектуре проект сверяй с:
   `python "D:\Создание программ\scripts\verify_memory.py"` (быстрая проверка целостности реестра памяти).
3. **Энергогигиена (Ops):** по завершении работы, если старый Linux-ПК больше не нужен для текущих задач — перевести его в сон (`python scripts/sleep_old_pc.py`); при необходимости — `wake_old_pc.py` (WOL).
